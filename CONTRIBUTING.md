# Contributing to Open Cognitive Memory

OCM welcomes contributions from researchers, engineers, students, and practitioners across cognitive science, psychology, neuroscience, AI, machine learning, knowledge representation, and data science.

## Ways to contribute

- Review literature and summarize evidence.
- Propose definitions, ontology terms, or research questions.
- Design or critique experimental protocols.
- Build reproducible baselines and evaluation tools.
- Improve dataset cards, annotation guidance, and privacy documentation.
- Replicate experiments and report negative results.
- Improve documentation and accessibility.

## Before starting

1. Read [VISION.md](VISION.md) and [GOVERNANCE.md](GOVERNANCE.md).
2. Search existing issues and discussions.
3. For substantial changes, open an issue describing the problem and proposed approach.
4. Separate evidence-backed claims from hypotheses and implementation proposals.

## Research contributions

Research proposals should include:
- Research question and motivation.
- Relevant prior work.
- Operational definitions.
- Hypotheses, where applicable.
- Methodology and comparison baselines.
- Data requirements and consent/privacy implications.
- Evaluation metrics and analysis plan.
- Limitations and expected failure modes.
- Reproducibility requirements.

## Code contributions

- Keep changes focused and documented.
- Include tests for new behavior.
- Provide reproducible commands and environment details.
- Avoid committing credentials, personal data, or restricted datasets.
- Record data sources and licenses.
- Prefer small pull requests with clear rationale.

## Dataset contributions

Do not submit personal or sensitive data to the repository. Dataset proposals must include:
- Collection purpose and protocol.
- Data provenance and ownership.
- Consent and legal/ethical basis.
- Data minimization and retention approach.
- Risk of identification or sensitive inference.
- Access restrictions and license.
- Dataset card and versioning plan.

Public availability of a dataset is not, by itself, proof that it can be redistributed.

## Pull request process

1. Link the pull request to an issue where possible.
2. Explain the change and its scientific or technical rationale.
3. Include tests, references, or reproducibility instructions as relevant.
4. Identify limitations and unresolved questions.
5. Respond constructively to review feedback.

## Quality expectations

Contributions should be precise, respectful, reproducible, and explicit about uncertainty. Negative or inconclusive results are welcome when methods are sound.

## Code of conduct

All contributors are expected to follow the project Code of Conduct.
